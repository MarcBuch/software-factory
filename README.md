# Software Factory CLI

Install dependencies with `bun install`, then run `bun run packages/cli/src/index.ts --help` (or `factory` after linking). Run inside a Git worktree. Initialize with `factory mission init`; default mode ignores `.factory/`, while `factory mission init --track` removes the exact generated ignore entry without touching unrelated rules. Use `factory mission init --skills` in a new project to install the `plan-mission` and `run-mission` skills under `.agents/skills/`; it refuses to overwrite an existing mission skill. The plan-first workflow is `factory plan create --input plan.json`, `factory plan approve <pln_id>`, then `factory plan materialize <pln_id>`; materialization creates a mission, milestones, and tasks with generated IDs. Manual missions remain supported through `factory mission create`, `factory mission milestone create`, and `factory mission task create`. Add `--json` to commands for automation; errors are JSON on stderr in JSON mode. Plan records live in `.factory/plans.jsonl`; executable missions live as one metadata line followed by one complete nested mission per line in `.factory/missions.jsonl`.

Task lifecycle statuses are `open`, `in_progress`, and `closed`. Use `factory mission update <task-id> --status open|in_progress` to update an active task, and `factory mission close <task-id> --reason "..."` to close one; closure reasons are required and must be nonempty. Reopening a task clears its previous closure reason. Use `factory mission ready` to list all open tasks with mission and milestone context, or `factory mission ready --mission <mission-id>` to scope the result to a mission; an unknown mission ID is an error.
